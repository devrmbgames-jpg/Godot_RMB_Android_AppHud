# Godot 3.6.2 + Apphud 3.4.2 + Google Play Billing 8.3.0

This plugin keeps the existing Godot-facing `GodotAppHud` API while updating the Android implementation to Apphud 3.4.2 and Google Play Billing 8.3.0.

## Build baseline

```text
Apphud SDK:             3.4.2
Google Play Billing:    8.3.0
Kotlin:                 2.3.21
Android Gradle Plugin:  8.13.2
Gradle:                 8.13
compileSdk:             36
targetSdk:              36
minSdk:                 26
JDK / JVM target:       17
Build Tools:            35.0.0
```

`minSdk 26` is retained because the current Apphud SDK requires API 26+.

## Godot Android library selection

For local development and production, put the exact Android AAR/JAR generated by the modified Godot engine into:

```text
app/libs/release/
app/libs/debug/
```

The build looks specifically for:

```text
godot-lib*.aar
godot-lib*.jar
```

Selection order is variant-specific:

1. local custom Godot library if present;
2. otherwise `org.godotengine:godot:3.6.2.stable` from Maven Central.

Both are `compileOnly`, so no Godot engine AAR is embedded into `GodotAppHud.*.aar`.

## Godot API compatibility

The public Godot methods remain:

```text
start(apiKey, userID, isObserver)
start_manual(apiKey, userID, deviceID, isObserver)
get_user_id()
get_device_id()
track_purchase(productId, offerIdToken, paywallId, placementId)
logout()
```

Apphud 3.4.2 changed its Kotlin API internally, especially `start(...)` overloads and nullable `userId()` / `deviceId()`. The bridge adapts those changes internally and keeps the Godot signatures unchanged.

## Install into Kidduca

Copy the built AAR and descriptor to:

```text
res://android/plugins/GodotAppHud.release.aar
res://android/plugins/GodotAppHudRelease.gdap
```

The descriptor should resolve:

```text
com.apphud:ApphudSDK-Android:3.4.2
com.android.billingclient:billing-ktx:8.3.0
androidx.appcompat:appcompat:1.7.0
```

Do not keep the old Apphud 2.7.3 / Billing 7 dependencies in the consuming Godot project. Mixing Apphud 2.7.3 with Billing 8.3.0 causes a runtime `NoSuchMethodError` because the old SDK calls the removed parameterless `BillingClient.Builder.enablePendingPurchases()` API.

## CI

GitHub Actions uses JDK 17 and the public Godot 3.6.2 compile-only fallback to run:

```text
:app:checkReleaseAarMetadata
:app:assembleRelease
javap Godot public ABI verification
dependencyInsight verification for Billing 8.3.0
```

The produced artifact is:

```text
app/build/outputs/aar/GodotAppHud.release.aar
```

Before release, also build against the exact modified Godot AAR and test Apphud initialization in the same Kidduca build that contains `GodotGoogleBilling`, verifying that the final dependency graph resolves a single Billing 8.3.0 generation.
